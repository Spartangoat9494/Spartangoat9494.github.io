4.0 Security Operations

Security Operations involves daily operational activities that maintain system, network, and application security. This domain includes incident response, forensics, logging/monitoring, disaster recovery, organizational security strategies, physical/environmental controls, OT/IoT security, and cloud security.

Important

The primary goal is maintaining confidentiality, integrity, and availability while ensuring operational efficiency.

4.1 Conduct Incident Response Operations

Overview

Incident Response (IR) is a structured methodology to identify, respond to, and recover from security incidents. Effective IR minimizes downtime, reduces damage, and preserves evidence.

Objectives

  • Detect security incidents promptly
  • Contain threats to prevent propagation
  • Preserve evidence for forensics or legal actions
  • Restore normal operations safely
  • Refine response procedures for future incidents

Incident Response Lifecycle

1. Preparation

  • Develop and maintain IR policies, playbooks, and standard operating procedures
  • Pre-stage tools: forensic suites, write blockers, packet analyzers
  • Maintain contact lists: IT, legal, executives, vendors, law enforcement
  • Conduct tabletop exercises, simulations, and drills
  • Maintain secure baselines for systems, applications, and devices

2. Identification

  • Detect incidents through:
    • SIEM alerts (correlated logs, anomaly detection)
    • IDS/IPS notifications (signature/behavioral)
    • Endpoint monitoring (EDR/XDR alerts)
    • User reports (phishing, social engineering)
  • Validate incident: determine true vs. false positive
  • Classify incident type: malware, insider threat, DDoS, data breach

3. Containment

  • Short-term containment: isolate affected hosts, block malicious traffic, disable accounts
  • Long-term containment: apply patches, implement network segmentation, enhance monitoring

4. Eradication

  • Remove malware, rootkits, backdoors, and unauthorized accounts
  • Close exploited vulnerabilities
  • Rebuild or restore systems to secure state

5. Recovery

  • Bring systems safely back online
  • Validate integrity using:
    • Hash checks
    • Baseline comparisons
    • System logs
  • Continuous monitoring for re-infection

6. Lessons Learned

  • Conduct post-incident review meeting
  • Document attack vector, response effectiveness, and lessons
  • Update IR playbooks, policies, and training programs

Tools and Techniques

  • Packet analyzers: Wireshark, tcpdump
  • Forensic imaging: FTK Imager, dd
  • Memory analysis: Volatility, Rekall
  • SIEM platforms: Splunk, ELK Stack, QRadar
  • Endpoint detection: CrowdStrike, Defender for Endpoint
Note

Preparation and planning are as important as response. The faster you identify and contain, the less damage occurs.

4.2 Utilize Digital Forensics Techniques

Overview

Digital forensics involves the collection, preservation, analysis, and presentation of digital evidence. Forensics ensures evidence remains admissible and intact.

Goals

  • Identify attacker behavior and techniques
  • Reconstruct timelines
  • Support incident response
  • Provide evidence for legal actions

Chain of Custody

  • Document every person handling evidence
  • Record date/time, collector, storage, and access
  • Ensure evidence integrity to maintain admissibility

Order of Volatility

  1. CPU registers and cache
  2. RAM (running processes, network connections)
  3. Network connections, routing tables
  4. Disk storage (persistent files)
  5. Backups/archives

Forensic Techniques

File System Analysis

  • Recover deleted files
  • Examine NTFS MFT, Linux inodes
  • Detect hidden partitions and steganography
  • Identify anomalous file timestamps and metadata

Memory Analysis

  • Identify memory-resident malware and injected processes
  • Extract encryption keys and session tokens
  • Examine process behavior and loaded modules

Disk Imaging

  • Create exact bit-for-bit copies using write blockers
  • Verify integrity with SHA-256 hashes
  • Maintain full documentation of image creation

Log Analysis

  • System, application, authentication, and network logs
  • Detect lateral movement, privilege escalation, abnormal login patterns
  • Identify unauthorized service creation or configuration changes

Network Forensics

  • Analyze PCAPs for suspicious traffic
  • Detect C2 communications or beaconing
  • Examine unusual port or protocol usage
Important

Volatile data (RAM, CPU) must be collected first because it disappears when power is lost.

4.3 Implement Organizational Security Strategies

Overview

Organizational security strategies reduce risk and protect assets through structured policies, processes, and controls.

Security Awareness

  • Social engineering defense
  • Password hygiene and MFA awareness
  • Phishing recognition and reporting
  • Clean desk policy and device handling

Access Management

  • Enforce least privilege and need-to-know
  • Role-based access control (RBAC)
  • Periodic access audits and removal of orphaned accounts
  • Identity lifecycle management (create, modify, disable)

Risk Management

  • Identify, analyze, prioritize, and treat risks
  • Risk treatment options:
    • Accept – tolerate risk
    • Avoid – change process to eliminate risk
    • Transfer – outsource or insure
    • Mitigate – apply controls

Configuration & Change Management

  • Maintain secure baselines for OS, apps, and devices
  • Patch management via controlled change process
  • Remove unnecessary services/software
  • Track all configuration changes for audit purposes

Vendor & Third-Party Security

  • Assess supplier security posture and compliance
  • Require SLAs, security questionnaires, pen test reports
  • Monitor access and network connections continuously
Note

Strong organizational security combines technical, administrative, and physical controls.

4.4 Apply Security to Cloud Services

Overview

Cloud security protects data, apps, and infrastructure in public, private, or hybrid cloud environments.

Key Concepts

  • Shared responsibility model:
    • Provider: infrastructure and physical security
    • Customer: data, identity, configuration, apps
  • Identity and Access Management (IAM):
    • Roles, MFA, conditional access, policy enforcement
  • Logging and monitoring: CloudTrail (AWS), Activity Logs (Azure), Audit Logs (GCP)
  • API security: token authentication, rate limiting, zero-trust segmentation

Tools & Techniques

  • CASB (Cloud Access Security Broker) – monitor cloud app usage
  • Encryption in transit and at rest
  • Continuous monitoring and compliance scanning
Important

Cloud security requires both technical and administrative measures for compliance and data protection.

4.5 Implement Disaster Recovery & Business Continuity

Overview

DR and BC ensure organizations continue operations during and after a disruption.

Key Metrics

  • RTO (Recovery Time Objective) – Maximum allowable downtime
  • RPO (Recovery Point Objective) – Maximum data loss

Backup Types

  • Full – complete backup
  • Incremental – changes since last incremental backup
  • Differential – changes since last full backup

Recovery Sites

  • Hot – fully operational, immediate failover
  • Warm – partially preconfigured, moderate recovery
  • Cold – minimal infrastructure, longest recovery, lowest cost
Note

Choosing the right site depends on business criticality, RTO, and budget.

4.6 Physical Security Controls

Overview

Physical security protects personnel, equipment, and facilities from threats.

Control Types

  • Deterrent: fences, lighting, signage
  • Preventive: locks, biometrics, mantraps
  • Detective: cameras, alarms, motion sensors
  • Compensating: guards, temporary measures

Best Practices

  • Layered physical security
  • Regular inspections and testing
  • Integration with IT and security monitoring

4.7 Environmental Controls

  • Temperature and humidity regulation
  • Fire suppression: clean agents, CO₂, water mist
  • Redundant power: UPS, generators
  • Cable management: EMI shielding, plenum-rated cables
Important

Environmental controls prevent equipment failure and downtime.

4.8 Secure OT, IoT, and Industrial Systems

OT Security

  • Includes PLCs, SCADA, ICS
  • Availability is critical; confidentiality secondary
  • Measures: network segmentation, monitoring unsafe commands, vendor patch coordination

IoT Security

  • Update firmware regularly
  • Change default credentials
  • Network segmentation
  • Disable unnecessary services
Note

IoT and OT devices often lack built-in security; monitoring and segmentation are essential.

4.9 Security Data Sources

Overview

Security data sources support monitoring, detection, and forensics.

Log Data Types

  • System logs – OS events
  • Application logs – app errors, user actions
  • Network logs – routers, firewalls, VPNs
  • Authentication logs – logins, account changes
  • Endpoint logs – AV alerts, EDR telemetry

Tools and Techniques

  • SIEM – log aggregation, correlation, alerting
  • EDR/XDR – endpoint monitoring, lateral movement detection
  • FIM – detect unauthorized file changes
  • DLP – prevent sensitive data exfiltration
  • Vulnerability scanning – detect misconfigurations

Log Retention & Management

  • Centralize logs for correlation and analysis
  • Retain logs according to policies and compliance
  • Protect logs from tampering or deletion
Important

Logs are critical for incident detection, investigations, and compliance.
